# 故障诊断 Agent 图谱与拓扑聚合、钻取及自适应缩放基线 V2.0

## 1. 核心不变量

1. 首屏可见节点约 36，允许 30～40；
2. 常态深钻不超过 60；80 仅为临时安全硬上限；
3. 拓扑和图谱都支持聚合、展开、上钻和下钻；
4. 聚合是前端投影，不新增真实对象，不修改 Case；
5. 关键对象和关键路径不能被聚合隐藏；
6. 展开局部稳定，禁止全局重新洗牌；
7. 三类 Case 共用规则，禁止按 `case_id` 特判。

## 2. 实现层次

```text
Ontology/Case Graph
→ Runtime Diagnosis Overlay
→ Projection Groups
→ Layout Anchors
→ Camera & Interaction
```

## 3. 聚合层级

### 实例拓扑

```text
业务域
→ 主机/虚拟化域
→ 网络Fabric
→ 存储系统
→ 前端端口/控制器/服务
→ LUN/文件系统/池
→ 硬盘框/磁盘
```

优先按 `CONTAINS` 与明确资源域聚合。共享资源不能被复制成多份；可通过多个边连接同一聚合节点。

### 故障知识图谱

```text
故障现象域
→ 故障模式域
→ 机制域
→ 证据要求域
→ 处置知识域
```

不得按画布空间或字符串前缀随意聚合。

### 跨层映射

若两端任一端聚合，映射边合并为带 `mapping_count` 的聚合映射；两端展开后按真实 entity mapping 拆分。

## 4. 投影状态

| 状态 | 含义 |
|---|---|
| `COLLAPSED` | 子项隐藏，显示聚合摘要 |
| `EXPANDED` | 显示当前层直接子项 |
| `FOCUSED` | 显示目标最小上下文，其余降暗 |
| `DETACHED_CRITICAL` | 关键子项从收起组中拆出单独显示 |

当父组收起但子项是根因、Agent 当前对象或异常对象时，采用 `DETACHED_CRITICAL`，并显示其所属父组引用。

## 5. 聚合摘要

```yaml
projection_group:
  group_id: pg-storage-01-controllers
  domain: INSTANCE_TOPOLOGY
  member_refs: [controller-0a, controller-0b]
  visible_member_count: 2
  total_member_count: 2
  anomaly_count: 1
  candidate_count: 1
  highest_severity: CRITICAL
  status: COLLAPSED
  anchor_node_id: storage-01
```

摘要至少显示总数、异常数、候选数和最高严重度。

## 6. 关键对象保留

不可完全隐藏：

- 已确认根因对象；
- 领先候选对象；
- `agent_focus` 对象；
- `user_selection` 对象；
- 严重异常对象；
- 最小证据链的对象；
- 当前高亮路径的端点和关键中继；
- 远程复制两端设备与复制会话；
- 扰邻场景中的受害者、共享资源和施压者。

## 7. 下钻与上钻

- 单击选中，双击或显式按钮展开；
- 面包屑显示当前语义路径；
- 下钻到无子级时进入对象详情，不空展开；
- 上钻恢复父层布局锚点；
- “仅看此路径”只改变过滤/强调，不改变真实拓扑；
- 对象展开失败显示缺失原因，不生成推测节点。

## 8. 局部布局

展开时：

1. 锁定原聚合节点世界坐标为锚点；
2. 在锚点邻域为子项分配局部扇形/环形/分层空间；
3. 只对一跳邻居进行柔性位移；
4. 非相关区域保持原坐标；
5. 动画结束后保存布局书签。

力导向图必须支持固定点和局部冷启动；禁止重新加热全图。

## 9. 自适应相机

自动缩放的目标包围盒包括：目标节点、必要标签、关键路径和相关映射边。边距为 10%～15%。

触发条件：用户显式“聚焦/适配视图”、首次进入场景、回放跳转且用户未自由浏览。若处于 `USER_EXPLORING`，只提示目标方向，不改变相机。

相机动画建议 350～650ms；跨双平面跳转可到 800ms。避免快速连续缩放造成眩晕。

## 10. 语义缩放

| 距离 | 显示 |
|---|---|
| 远景 | 领域/设备聚合、异常数量、关键路径 |
| 中景 | 资源节点、故障模式、主关系和候选标记 |
| 近景 | 属性摘要、证据徽标、端口/控制器等细粒度节点 |

语义缩放只改变可见细节，不自动执行上钻/下钻。

## 11. 三类投影模板

### 单设备双控制器

保留业务→SAN→双端口→双控制器→BlockService→LUN 的主路径，突出主备关系和接管链。

### 双业务共享资源

左右分别放 Host-A/业务A 与 Host-B/业务B，中间汇聚共享端口、控制器或池。默认从受害者B路径聚焦；发现共享瓶颈后展开 sibling consumer A。

### 双设备远程复制

源端设备和目标端设备分别形成边界容器，中间显示 ReplicationSession 与 Link。业务前端链、源端后端链、复制链和远端落盘链可独立强调。

## 12. 性能验收

- 30～40 节点首屏稳定交互；
- 常态 60 节点维持目标帧率；
- 80 节点触发降级提示与聚合，不作为常态；
- 展开/收起不造成全图跳变；
- 同一实体在三视图中保持统一 ID；
- 聚合映射数量与真实映射一致；
- 关键对象保留规则对三类 Case 均通过。
