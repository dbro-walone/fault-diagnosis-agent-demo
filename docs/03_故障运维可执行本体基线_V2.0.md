# 故障运维可执行本体基线 V2.0

## 1. 定位

本体不是一张静态知识图，而是把运维领域对象、关系、观测、诊断动作和状态变化组织为可查询、可推理、可执行、可审计的统一语义层。

V2 借鉴 Ontology 思维，将系统分成：

- Objects：业务、主机、网络、存储设备、端口、控制器、服务、LUN、池、磁盘、复制会话；
- Links：承载、访问、连接、包含、依赖、主备、共享、复制、影响、因果；
- Properties：对象身份、状态、性能、容量和角色；
- Actions：查询、验证、展开路径、创建候选、重规划、确认结论；
- Functions/Rules：候选生成、时间对齐、影响传播、证据链检查；
- Events：告警、日志、KPI异常、状态切换、Planner/Skill/推理事件。

## 2. 四类状态必须隔离

| 状态层 | 内容 | 是否可写回本体 |
|---|---|---:|
| Source State | CMDB、拓扑、告警、日志、KPI原始数据 | 由源系统管理 |
| Ontology State | 领域对象、关系和允许持久化的业务语义 | 是，受动作权限控制 |
| Diagnosis State | Fact、Evidence、Candidate、Plan、Conclusion | 写入诊断会话，不改源对象事实 |
| Projection State | 聚合组、相机、展开、user_selection、View Model | 否，仅前端临时状态 |

Projection Group 不是资源，不能生成新的 CMDB ID；`FactDetailViewModel` 也不是 Fact。

## 3. 核心对象类型

| 类别 | Object Type 示例 |
|---|---|
| 业务 | BusinessService、Application、Workload |
| 计算 | Host、VM、Container |
| 网络 | Fabric、Switch、Link、Port |
| 存储 | StorageSystem、Controller、Service、LUN、FileSystem、Pool、Enclosure、Disk |
| 容灾 | ReplicationSession、RemoteDevice、ConsistencyGroup、RecoveryPoint |
| 观测 | AlarmEvent、LogEvent、MetricSeries、MetricWindow、ResourceState |
| 诊断 | Symptom、CanonicalFact、Evidence、CandidateHypothesis、DiagnosisSession、PlanTask、Conclusion |
| 知识 | FaultMode、FailureMechanism、EvidenceRequirement、RepairPlaybook、HistoricalCase |

## 4. 核心关系

| Link Type | 示例 | 语义 |
|---|---|---|
| `CONTAINS` | StorageSystem→Controller | 资源包含 |
| `CONNECTS_TO` | HostPort→Fabric | 物理/通信连接 |
| `ACCESSES` | Host→LUN | 业务访问 |
| `DEPENDS_ON` | BusinessService→LUN | 依赖 |
| `ACTIVE_STANDBY_WITH` | ControllerA↔ControllerB | 主备 |
| `SHARES` | HostA/HostB→StoragePool | 共享资源 |
| `REPLICATES_TO` | LocalLUN→RemoteLUN | 复制 |
| `OBSERVED_ON` | Fact→Resource | 观测对象 |
| `SUPPORTS/WEAKENS` | Evidence→Candidate | 诊断作用 |
| `EXPLAINS` | Candidate→Symptom | 解释现象 |
| `CAUSES` | FailureMechanism→FaultMode | 知识因果 |
| `IMPACTS` | FaultMode→BusinessService | 影响 |

## 5. Canonical Fact 进入本体的边界

Canonical Fact 是带来源、时间、覆盖和质量的诊断观测对象，可在 Diagnosis State 中作为一等实体。它不等同于源系统原始行，也不等同于 Evidence。

```text
原始日志行／告警／KPI样本
→ Canonical Fact
→ OBSERVED_ON 资源
→ DERIVED_FROM SkillExecution与SourceRef
→ Evidence解释
```

## 6. 故障知识层

一个 FaultMode 至少关联：

- 可解释的 Symptom；
- 可能发生的 ResourceType；
- FailureMechanism；
- 需要的 EvidenceRequirement；
- 可区分的 CompetingFaultMode；
- 可能影响的关系路径；
- 可选 RepairPlaybook。

候选生成不是“图谱命中即结论”，而是：

```text
Symptom→可能FaultMode
+ 实例拓扑定位到具体Object
+ 当前Fact细化模式
= CandidateHypothesis(Object + FaultMode)
```

## 7. 可执行动作

| Action | 输入 | 输出 | 权限 |
|---|---|---|---|
| NormalizeSymptom | 用户描述 | 标准化现象 | 诊断会话内 |
| MapBusinessResource | 业务对象 | 资源引用 | 只读 |
| QueryTopology | 对象、方向、跳数 | 关系子图 Fact | 只读 |
| QueryObservation | 对象、时间窗、指标 | Canonical Facts | 只读 |
| GenerateCandidates | 现象、图谱、拓扑 | 候选列表 | 会话内 |
| UpdateCandidate | Evidence | 分数/状态变化 | 会话内 |
| ConfirmRootCause | 证据链检查 | Conclusion | 会话内、规则保护 |
| PreviewRepair | Conclusion | 处置建议 | V2 只预览 |

动作必须产生审计事件；只有 Runtime 可以归并为诊断状态。

## 8. 三类场景本体表达

### 控制器热复位

```text
watchdog_timeout CAUSES CONTROLLER_WARM_RESET
Controller-0A ACTIVE_STANDBY_WITH Controller-0B
Controller-0A/0B PROVIDES BlockService
BlockService SERVES LUN-DB01
```

### 扰邻

```text
Host-A ACCESSES LUN-A
Host-B ACCESSES LUN-B
LUN-A/LUN-B SHARES StoragePool/Controller/Port
WorkloadBurst-A CAUSES SharedResourceContention
SharedResourceContention IMPACTS Host-B
```

关键推理动作是从受害者 B 的影响路径找到共享瓶颈，再沿 `SHARES` 关系反向定位施压者 A。

### 远程复制

```text
LocalLUN REPLICATES_TO RemoteLUN
ReplicationSession CONNECTS_TO ReplicationLink
ReplicationLink CONNECTS_TO RemoteDevice
ReplicationLag IMPACTS RecoveryPointObjective
```

需要区分本地前端、源端后端、复制链路、远端端口和远端写入五个故障域。

## 9. 图谱展示

- 实例对象与知识对象使用不同视觉语法；
- 诊断状态通过叠加标记表达，不改变对象基础类型；
- 聚合节点由 Projection Store 计算，不进入本体；
- 选中一个 Candidate 时可以显示最小解释子图：Symptom→FaultMode→Object→Fact→Evidence；
- 全量知识图谱允许 1,000+ 节点，但默认必须按语义域聚合。

## 10. 规则与约束

1. 任何 Conclusion 必须引用 Candidate 和满足的 EvidenceRequirement；
2. Evidence 必须引用 Canonical Fact；
3. Fact 必须保留来源、对象、时间和覆盖信息；
4. 共享关系和复制关系必须来自源拓扑或明确知识配置，前端不得推测；
5. 相似案例只作为辅助引用，不单独确认根因；
6. View Model、聚合组和相机状态不得写回 Ontology State；
7. 处置动作需要权限、审批、验证和回滚，V2 不执行。

## 11. 验收

- 三类 Case 都能用同一套 Object/Link/Action/Fact/Evidence 语义表达；
- 从 Conclusion 可追溯至 Candidate、Evidence、Fact、SkillExecution 和源引用；
- 图投影展开/收起不改变 Ontology State；
- Runtime 事件可审计每次诊断动作和状态变化；
- 前端不出现不可追溯的推测节点或关系。
