# 实例拓扑视图展示与交互规格 V2.0

## 1. 目标

实例拓扑必须让用户快速区分设备外与设备内、业务路径与故障传播路径，并支持从业务现象逐层定位到具体存储对象。

## 2. 九层语义空间

| 层 | 典型对象 | 空间域 |
|---|---|---|
| 1 | BusinessService/Application | 设备外·业务 |
| 2 | VM/Host | 设备外·计算 |
| 3 | IP/FC Network、Fabric、Switch | 设备外·网络 |
| 4 | FrontendPort | 存储边界 |
| 5 | Controller/Node | 设备内·控制 |
| 6 | Block/File/Replication Service | 设备内·服务 |
| 7 | LUN/FileSystem | 设备内·逻辑对象 |
| 8 | StoragePool/Tier | 设备内·资源池 |
| 9 | Enclosure/Disk | 设备内·硬件 |

不要求所有 Case 展示全部九层；必须根据本次诊断范围投影最小必要层级。

## 3. 空间布局

- 业务流总体从上/左向下/右；
- 每台 StorageSystem 使用明确边界容器；
- 多设备场景并列边界容器，不将远端设备画进源端容器；
- 共享资源放在消费者路径汇聚位置；
- 主备控制器保持稳定相对位置；
- 复制会话位于两设备之间，不能伪装成物理端口。

## 4. 节点视觉

节点至少表达：资源类型、名称、运行状态、诊断叠加、聚合摘要。建议使用：

- 基础几何/图标：资源类型；
- 主体材质与弱色：正常状态；
- 外层光晕：异常/根因/候选；
- 描边：用户选中；
- 导航脉冲：Agent 当前对象；
- 徽标：受影响、接管、共享、复制。

标签分三档：远景只显示域与关键对象；中景显示对象名称；近景显示关键属性和状态值。

## 5. 关系视觉

| relation type | 示例 | 建议样式 |
|---|---|---|
| software | 应用→服务 | 细实线 |
| workload | Host→LUN I/O | 带流向粒子 |
| comm | 复制/网络通信 | 虚线＋箭头 |
| physical | 端口/链路 | 实线 |
| logical | 服务→LUN/池 | 半透明实线 |
| hardware | 控制器→硬件 | 结构线 |
| fault | 因果/影响 | 发光曲线或管道 |

任何关系必须带方向（若领域关系有向）、类型和 source/target ID；颜色不能成为唯一语义载体。

## 6. 节点预算

- 融合首屏 30～40，目标约 36；
- 单设备默认展示到控制器、服务和关键逻辑对象；
- 多设备先设备级聚合，再展开故障相关设备；
- 常态深钻不超过 60；
- 80 为安全硬上限，达到时禁止继续无约束展开。

## 7. 交互

### 节点

- 单击：选中并打开详情；
- 双击/展开按钮：下钻聚合或容器；
- 右键/更多：仅看路径、设为起点、复制 ID；
- Esc：退出聚焦并恢复书签；
- 点击空白：清除 user_selection，不清除 agent_focus。

### 路径

- 悬浮显示路径类型、方向和当前状态；
- 点击路径显示端点、关系属性和相关 Evidence；
- 故障路径、影响路径、恢复路径和冗余路径可同时存在，使用不同线型；
- “仅看此路径”属于 Projection Filter。

### 时间

- 时间线事件可定位当时状态；
- KPI 趋势上的告警/日志标记可反向定位拓扑对象；
- 回放不泄露后续节点状态。

## 8. 自动聚焦

Runtime 的 `agent_focus` 包含对象和路径引用。若用户未自由浏览，前端可以局部适配；用户已浏览时只以边缘导航提示。

根因确认后，自动聚焦目标为“根因对象＋最小影响链＋恢复节点”，不是只聚焦单一根因节点。

## 9. 右侧详情接口

对象详情最少包含：

```yaml
object_detail:
  object_id: controller-0a
  object_type: CONTROLLER
  name: Controller-0A
  containment_path: [storage-01, controller-0a]
  runtime_status: DEGRADED
  diagnosis_badges: [LEADING, AGENT_FOCUS]
  relationships: []
  fact_refs: []
  candidate_refs: []
  data_quality: COMPLETE
```

## 10. 三类场景验收

- 控制器 Case：可读出双 SAN、双控制器、主备接管和 LUN 影响；
- 扰邻 Case：可读出受害者 B、共享资源和施压者 A 的反向定位；
- 远程复制 Case：可读出本地业务链、复制会话、链路和远端落盘链；
- 设备边界、共享关系和复制方向均无歧义；
- 不存在重复资源或前端推测关系。
